# DNS浏览器 (WebShareApp)

> 应用显示名 v1.0.43 起是 **「DNS浏览器」**（此前叫「网页分享助手」）。包名 `com.webshare.app`
> 没变，覆盖安装即可，登录状态/标签页都在。

一个 Android 应用，用于挂载指定网页并接收系统分享内容。专为华为手机侧边快捷栏（智慧多窗）设计，可将分享的网址/图片传递给挂载的网页进行处理。

## 功能特性

- **WebView 网页挂载**：在应用内加载指定网页
- **接收分享内容**：接收来自其他应用分享的文本（网址）、图片和**视频 / 音频**；分享进来的文件自动送进页面的上传入口（页面没有上传入口时再手动点）
- **设置界面**：安全 DNS、应用更新；起始页改为内置的家庭日历（v1.0.78 起，地址在新建页面时输入）
- **多标签页**（v1.0.27 起）：底部「标签页」按钮打开浏览器式卡片切换器（带页面缩略图），可新建 / 切换 / 关闭标签页，最多 6 个，各标签页独立保持页面状态
- **下载到手机**：网页里的下载按钮 → 确认框选目录 → 走 App 自己的 DNS/TLS 通道下载，带进度通知；下载完成会浮出 3 秒「立即打开」按钮（v1.0.75 起；电视上可用遥控器 OK 直接打开，v1.0.76 起）；下载的 APK 点一下就能装（v1.0.68 起）
- **剪贴板可用**：`http://` 源下网页的「复制 / 粘贴」按钮也能正常工作（桥接 App 剪贴板）
- **文件上传**：网页 `<input type="file">` 可用，带文件的表单由 App 流式组装上传
- **新窗口链接交给系统浏览器**：`window.open` / `target="_blank"` 不再顶掉挂载的页面
- **网页视频能播就读得动**：把设备真实的解码能力（有没有 H.265 硬解）如实告诉网页，并把时间轴损坏的录像在播放前自动修好
- **语音朗读与录音**（v1.0.31 起）：网页的 `speechSynthesis` 朗读由 App 的系统 TTS 顶上（Android WebView 自己不带），`getUserMedia` 录音（学习站点的语音跟读）在 https 页面放行麦克风
- **安全 DNS (DoH)**：支持 DNS-over-HTTPS，可自定义 DoH 服务器，防止 DNS 劫持
- **记住网站登录**（v1.0.39 起）：登录过的站点（政务/统一认证这类跨域名跳转的也算）关掉 App、
  被系统清后台都不用重新登录；Cookie 只在设置页点「清除所有网站登录状态」时才清
- **语音快捷指令**（v1.0.39 起）：设置里给网址起个名字（如「乘车码」），长按桌面图标能直接点进去；
  手机助手（小艺 / 华为「快捷指令」）唤起 App 时也能直达指定那一页
- **标签页备注名 = 语音直达**（v1.0.44 起）：在标签页切换器里**长按标签页标题栏**就能给这一页起个备注名
  （如把乘车码那页叫「乘车码」），留空确定即恢复原名。备注名会自动变成桌面 / 助手的快捷指令，
  所以对小艺说「打开 DNS浏览器 乘车码」就直接切到那个标签页，**不用去设置页配置**
- **系统通知**（v1.0.44 起）：网页里的 `new Notification(...)` 由 App 转成系统通知（渠道「网页通知」，
  显示来源域名，点通知回到对应页面）；Android 13+ 首次打开时申请一次通知权限
- **已下载页批量操作**（v1.0.44 起）：长按任一条进入多选，可全选后**批量重试 / 批量分享 / 批量删除**
  （删除会先问「删除文件并移除记录」还是「仅移除记录」）
- **自定义 DNS 是可编辑下拉框**（v1.0.44 起）：点输入框列出常用 DoH 与 UDP DNS，选中即填入，也照旧能手输
- **登录回来别把我扔去首页**（v1.0.48 起）：厦门 i人才这类站点登录后会按服务端配置跳到首页，
  App 会把用户带回他原本要看的页面（比如「刷码乘车」），详见「方式 O」
- **历史网址一键复制**（v1.0.50 起）：新建标签页弹窗里，每条「最近访问」左边有个复制图标，
  点一下就把它复制到系统剪贴板（提示「已复制网址」），不用先打开页面再从地址栏里拖选。
  **地址输入框右边还有「✕」清空按钮**（v1.0.75 起），一点就把输入框清空、光标留在框里
- **到某地自动打开**（v1.0.50 起）：设置里填一个坐标 + 范围（米）+ 网址——走到那儿打开 App
  就直接进设好的那一页（比如到吕厝公交站打开就进「刷码乘车」）。只在打开 App 那一刻读一次位置
  （且只认 1 分钟内的定位，更旧就当场重新要一次），不做后台定位、不上报，详见「方式 P」
- **缓存视频、离线看**（v1.0.52 起）：网页里放视频时，**打开右下角三条线菜单、长按「已下载」**就开始缓存（一页有多个视频
  会列出来让你挑），存进 App 自己的目录后**不联网也能看**；缓存列表就在「已下载」页的「缓存视频」标签里
  （v1.0.54 起合并，不再单独占一个底栏入口），还能存到手机或分享出去。直链 mp4/webm、HLS 分片列表
  （含 fMP4）都行，TS 会自动换成 mp4，详见「方式 Q」
- **安卓电视 / 遥控器**（v1.0.53 起）：电视桌面（Leanback）能直接找到本应用；遥控器先移动焦点
  选中按钮/网页，再按 OK 执行——**网页要先按一次 OK 进入**，之后方向键才移动屏幕上的小圆点光标、
  OK 点击；长按 OK（或菜单键）切到工具栏；输入框用电视自带键盘；离线播放页铺满屏幕，
  ←/→ 快退快进 10 秒、OK 暂停/继续、↑/↓ 调音量。手机端行为完全不变，详见「方式 R」
- **缓存合进「已下载」**（v1.0.54 起）：原来的「缓存」入口去掉了，缓存视频变成「已下载」页里的
  第二个标签；网页里不再自动浮出「发现视频」提示条，改成**长按「已下载」**开始缓存
  （电视上：长按 OK 切到工具栏，打开三条线菜单，挪到「已下载」再长按 OK）
- **新底栏**（v1.0.55 起）：右下角只剩一个**三条线按钮**，点开竖向弹出 **新建页面 / 标签页 / 刷新 / 已下载 / 设置**
  （「新建页面」v1.0.70 起：打开和切换器同一套地址栏，下面列着最近访问过的地址；
  v1.0.75 起地址栏的「访问」和「取消」并排在底部，输入框右侧有清空按钮）；
  它左边是一排**标签页圆片**，当前页紫色；标签多了两侧出现 **‹ ›** 翻页箭头，标签条本身也能横向滑动；
  **长按圆片**弹出这一页的菜单（编辑页面 / 关闭；电视还有页面操作方式），
  菜单样式与右下角三条线菜单一致（v1.0.75 起：48dp 行高、紫色图标、单行文字），
  **从 v1.0.77 起菜单固定弹在这个圆片正上方**，不再贴着右下角；原来的「刷新页面」「标签页列表」
  两项已去掉（刷新走三条线菜单，切换器挪到三条线菜单的「标签页」）。「编辑页面」里除了备注名和
  页面字，**还能直接改网址**（v1.0.77 起，改完自动重新加载）。清缓存刷新仍可在三条线菜单里
  长按「刷新」，登录状态保留
- **页面字**（v1.0.56 起）：每个圆片上的字可以单独设——长按圆片 →「编辑页面」，
  在「编辑标签页」里填「页面字」；留空就按标题（或备注名）取第一个字，和网页标题完全独立
- **电视两段式操作**（v1.0.56 起）：焦点刚落到网页上只是**选中网页**（画一圈紫框、不显示光标，
  方向键不会挪光标），再按一次 OK 才进入光标模式；工具栏里左右可以逐个选中标签圆片，
  选中后按 OK 才切换页面。避免"只想选中却误点进页面"
- **JavaScript 接口**：网页可通过 JavaScript 获取分享内容、剪贴板、网络桥接

## 如何构建

### 方式一：GitHub Actions 在线构建（推荐，无需本地环境）

1. 推送代码到 GitHub，Actions 自动构建
2. 直接下载 Release APK（固定签名，可覆盖安装无需卸载）：

   ```
   https://github.com/ALphaGoDai/WebShareApp/releases/latest/download/DnsWeb.apk
   ```

   （v1.0.44 起产物名从 `WebShareApp.apk` 改成 `DnsWeb.apk`，Release 标题是 `DnsWeb v1.0.<构建号>`；
   老的 `…/download/WebShareApp.apk` 链接会失效，请用上面的新地址）

   手机浏览器打开此链接即可直接下载安装。也可在 App 设置中点击"下载最新版本"。

### 方式二：使用 Android Studio

1. 打开 Android Studio
2. 选择 `File > Open`，选择 `WebShareApp` 目录
3. 等待 Gradle 同步完成（Android Studio 会自动生成 gradle-wrapper.jar）
4. 点击 `Run` 按钮编译并安装到手机

### 方式三：使用命令行

1. 安装 Android SDK（设置 `ANDROID_HOME` 环境变量）
2. 创建 `local.properties` 文件：
   ```
   sdk.dir=C\:\\Users\\你的用户名\\AppData\\Local\\Android\\Sdk
   ```
3. 运行 Gradle Wrapper（如果缺少 gradle-wrapper.jar，先安装 Gradle 8.0 并运行 `gradle wrapper`）
4. 执行构建：
   ```
   ./gradlew assembleRelease
   ```
5. APK 输出路径：`app/build/outputs/apk/release/app-release.apk`

> 注意：构建依赖仓库根目录的 `release.keystore` 签名文件（CI 首次构建会自动生成并提交）。所有构建使用同一签名，因此可以直接覆盖安装，无需卸载旧版本，应用设置也会保留。

## 使用方法

### 1. 首次使用

1. 打开应用即加载默认网页——**家庭日历 `https://date.nbhonghong.top:7777/`**（v1.0.78 起；
   站点地址内置于 App，v1.0.29 起设置页不再有「网页地址」一项，地址都在「新建标签页」的地址栏里输）
2. 想去别的地址：右下角三条线 →「新建页面」→ 输入网址 → 底部「访问」（和「取消」并排；
   输入框右侧的 ✕ 可以一键清空）
3. 设置页里剩下的都是安全 DNS (DoH) 与应用更新相关选项

### 2. 配置分享内容传递

分享内容有两种传递方式：

**方式 A：URL 占位符（需自行改 App 内置地址，v1.0.29 起设置页没有网址项）**

在设置中将 URL 配置为包含 `{shared}` 占位符，例如：
```
https://your-website.com/process?url={shared}
```
分享内容会替换 `{shared}`（URL 编码后）。

**方式 B：自动附加参数**

如果 URL 不包含 `{shared}`，分享内容会自动以查询参数附加：
```
https://your-website.com?shared=<url_encoded_content>
```

**方式 C：JavaScript 接口**

网页加载后可通过 JavaScript 获取分享内容：

```javascript
// 方式1：回调函数（页面加载完成后自动调用）
window.onSharedContent = function(data) {
    console.log('收到分享内容:', data.type, data.content);
    // data.type: "text" 或 "image"
    // data.content: 分享的文本或图片URI
};

// 方式2：主动调用
var sharedText = Android.getSharedText();   // 获取分享文本
var sharedType = Android.getSharedType();    // 获取分享类型
var settings = Android.getSettings();        // 获取应用设置(JSON)
```

**方式 D：Android.httpPost / Android.httpGet 网络桥接**

由于部分网络环境下系统 DNS 被劫持，WebView 原生 POST/fetch 请求会失败。网页可改用 App 提供的网络桥接（自动走 App 的自定义 DNS + TLS，且兼容 reason phrase 缺失的服务器）：

```javascript
// POST（异步，回调收到结果）
Android.httpPost(
    "https://send.nbhonghong.top:7777/api",     // 请求地址
    "url=https://example.com&foo=bar",           // 请求体
    "application/x-www-form-urlencoded",         // Content-Type（JSON 则传 "application/json"）
    "onPostDone"                                  // 回调函数名（全局函数，可传 "" 用默认 window.onHttpPostResult）
);

function onPostDone(r) {
    // r = { ok: true, status: 200, data: "响应体文本", error: null }
    if (r.ok) {
        console.log('HTTP', r.status, r.data);
    } else {
        console.error('失败:', r.error);
    }
}

// GET（异步，回调格式相同）
Android.httpGet("https://send.nbhonghong.top:7777/api?url=xxx", "onGetDone");

// 带文件的表单上传（文件必须来自网页 <input type="file">，App 按「文件名+大小」
// 找回系统文件选择器授权过的真实文件，流式读取，不经过 base64）
Android.httpPostForm(
    "https://send.nbhonghong.top:7777/api/upload",
    JSON.stringify({
        headers: { "X-Device-Id": "xxx" },
        fields:  [{ name: "cat", value: "待分类" }],
        files:   [{ name: "files", filename: "a.jpg", size: 123456 }]
    }),
    "onUploadDone"     // 回调格式同 httpPost，只是 data 是服务端响应文本
);

// 剪贴板 / 外部浏览器（注入脚本已自动接管 navigator.clipboard 与 window.open，
// 网页一般不需要直接调用）
Android.copyText("要复制的文本");           // 返回是否成功
Android.readClipboard();                    // 返回剪贴板文本（需 App 在前台）
Android.openExternal("https://example.com"); // 用系统浏览器打开

// 真实解码能力（注入脚本已用来自动修正 canPlayType / MediaSource.isTypeSupported，
// 网页若想自己判断可以读这个）
JSON.parse(Android.mediaCaps());
// → { "hevc": true, "hwHevc": false, "sdk": 35 }
//   hevc    : 这台设备能不能解 H.265（软解也算）
//   hwHevc  : 是否是硬件解码
//   sdk     : Build.VERSION.SDK_INT
```

> 说明：桥接请求全部走 `shouldInterceptRequest` 同一套 DNS/TLS 逻辑（DoH 优先、明文被拒自动切 TLS），因此和主页面加载行为一致。回调在主线程执行，可安全操作 DOM。

**方式 E：自动接管 fetch / XMLHttpRequest（推荐，网页零修改）**

v1.0.11 起，App 在页面加载时自动注入接管脚本，网页无需任何修改：

- 页面里的 `fetch` / `XMLHttpRequest`（含 jQuery `$.ajax`）先走 WebView 原生请求
- 原生请求网络级失败时（典型场景：系统 DNS 被劫持到 127.0.0.1），自动改走 App 内部 DoH + TLS 通道重发
- 返回值/事件与原生一致（Promise、`onload`、`onerror`、`responseText` 等），对网页代码完全透明

已知限制：
- WebSocket、原生表单提交（`<form action>` 跳转）不在接管范围
- 请求体支持：字符串、`URLSearchParams`、`FormData`（含文件，走 `httpPostForm` 桥接）、Blob 文本

### 方式 F：下载网页资源到手机（v1.0.24 起）

网页里的下载按钮（`<a download>` 或服务器返回 `Content-Disposition: attachment`）会调用到 App：

1. 弹出确认框显示文件名与大小，让用户选择保存位置：
   - **系统下载目录 Download/**（默认，走 MediaStore，无需任何权限）
   - 之前选过的目录（SAF 授权持久化，跨重启有效）
   - **＋ 选择其他目录…** 打开系统目录选择器（可在里面新建文件夹）
   - 注意：Android 11+ 不允许把「下载」根目录直接授权给应用，需要选它的子目录
2. 确认后由前台服务下载，**走 App 自己的 DoH + TLS 通道**（系统 DownloadManager 用的是被劫持的系统 DNS，且带不上网页登录 Cookie）
3. 通知栏显示进度，完成后可点通知直接打开文件；同一目录重名会自动改名
   - **下载完成浮按钮**（v1.0.75 起）：下载完成时，如果 App 正在前台，底栏上方会浮出一个
     紫色「立即打开」按钮，点一下直接打开刚下载的文件；**只停 3 秒**，自动消失，
     错过就还从通知或「已下载」里打开。电视上它会拿到遥控器焦点（带紫色焦点框），
     3 秒内按 OK 就能打开文件；自动消失后焦点还给网页（v1.0.76 起）。
4. **下载的 `.apk` 直接安装**（v1.0.68 起）：在「已下载」里点这条记录（或点完成通知的「打开」）
   会直接拉起系统安装器。网页服务器把 APK 标成 `application/octet-stream` 也能认出来——App 会按
   扩展名补成 `application/vnd.android.package-archive`（电视的安装器只认这个类型）。
   电视/手机第一次安装时，系统若问「是否允许 DNS浏览器 安装未知应用」，选允许即可
5. **批量管理**（v1.0.44 起）：在「已下载」页**长按任一条**进入多选（顶栏显示「已选 N 项」、可一键全选，
   底栏是重试 / 分享 / 删除）；删除可选「删除文件并移除记录」或「仅移除记录」，分享走系统分享面板，
   重试只对下载失败的条目生效。选择模式下按返回键先退出多选，不会直接离开这一页

### 方式 G：剪贴板（复制 / 粘贴）

App 内网页常见是 `http://` 源（非安全上下文），此时 `navigator.clipboard` 整个不存在、
`document.execCommand('paste')` 也被禁用 —— 页面上的「复制」按钮点了毫无反应。

v1.0.24 起注入脚本会把 `navigator.clipboard`（`writeText` / `readText`）接到 App 的
`ClipboardManager` 上：优先用浏览器原生实现，失败或不存在时自动走 App 剪贴板，
网页代码无需改动。

### 方式 H：文件上传（`<input type="file">`）

1. 网页点「上传」→ 系统文件选择器（`onShowFileChooser`），可多选
2. 选中后网页的 `FormData` 带文件提交：原生请求失败时，注入脚本把「字段 + 文件名 + 大小」
   交给 App，App 用系统文件选择器授权过的真实文件**流式**组装 multipart 上传
   （文件内容不经过 JS，也不走 base64；`Content-Length` 按文件流实测，避免被服务器判为协议错误）
3. 同样自动在两个协议（http/https）间回退，兼容 http 源 + TLS 端口的站点

### 方式 I：新窗口链接（`window.open` / `target="_blank"`）

`window.open()` 与 `target="_blank"` 的链接（例如页面里的「浏览器打开」「打开原页面」）
由系统浏览器打开，App 窗口停留在当前页，不会把挂载的网页顶掉。

### 方式 J：网页视频能播就读得动（v1.0.18 起）

站点里播放监控 / 门锁录像（「有人经过」「按门铃」这类标签）时，安卓 WebView 常报
`MEDIA_ERR_DECODE`，页面上就是「加载失败，正在重试…」然后「解码失败」。这不是网页的锅，
录像本身和交付方式各有毛病：

1. **MP4 时间轴塌陷**：录到末尾时一批帧的时间戳被压成 62～125 微秒（正常应该是 30 毫秒级），
   而这批帧的数据同时是错位的（HEVC NAL 单元没对齐、AAC 帧解不出来）。安卓的音频解码器
   碰到第一个这种包就直接躺平，`<video>` 于是报解码错误。
2. **能力上报不实**：网页用 `canPlayType('video/mp4; codecs="hev1"')` 判断能不能播 H.265，
   回答来自 WebView 的 Chrome 内核而不是设备本身——有的 ROM / 旧 WebView 会对 H.265 一律
   乐观作答，网页于是挑了一个本机其实解不了的码流，播到一半就是「解码失败」；
   B 站这类走 MSE 的播放器看的是 `MediaSource.isTypeSupported`，同样的问题。
3. **Range / 206 分段交付**：站点对本地文件按 `Range` 回 206，WebView 的媒体管线吃一串
   被截断、反复重取的 206，会在第一个 GOP 之后报解码错误——同一份文件整份发过去就能播完。

App 的三种处理：

- **如实上报能力**：注入脚本启动时调 `Android.mediaCaps()`（读 `MediaCodecList`），
  设备有 H.265 解码器时继续沿用内核的判断（VP9 / AV1 有内核软解，绝不能降级），
  只有设备确实没有 H.265 解码器、内核却声称能播时，才把 `canPlayType` /
  `isTypeSupported` 里 hevc/h265 的答案改成「不支持」——让网页老老实实走服务端转码。
- **播放前修好录像**：拦截到视频响应时（`video/*` 或 .mp4/.mov/.mkv 等后缀）先扫一遍采样表，
  发现塌陷就把尾部那段坏帧丢掉、原地改采样表（不重编码、不动一字节采样数据），修好的结果按
  URL 缓存在应用缓存目录，同一个视频只修一次。健康视频一帧不动，只多一次扫描。
- **整份交付视频**：从第 0 字节开始的视频请求，一律把整个文件取回来以 200 一次交出
  （去掉 `Content-Range` / `Content-Length` / `Accept-Ranges`），绕开 206 分段这条踩过坑的路径。

「下载到手机」走的是同一套修复：存到本地 / NAS 上的也是修好的文件，通知栏会写明
「已修复录像尾部损坏帧（丢弃 N 个损坏音频帧）」。超过 32 MB 的文件不修（采样表要整包进内存，
太大就跳过，交给服务端转码兜底）；超过 64 MB 的视频仍按原来的 Range 方式交付。

### 方式 K：把手机里的文件分享给站点（v1.0.20 起；v1.0.21 起自动上传）

相册 / 文件管理器里选「分享」时，系统分享面板里会出现本应用（`ACTION_SEND` 与
`SEND_MULTIPLE`，类型覆盖 `image/*`、`video/*`、`audio/*`，和站点 `<input accept>` 一致）。
分享进来之后**不用再点任何按钮**：

1. App 记下文件的 `content://` 地址、登记成「刚选过的文件」，带在网址后面打开站点
   （`?shared=...`，走的就是第 2 步配的那套分享内容传递）；
2. 页面一加载完，App 把文件挂到**同源虚拟地址**上，注入脚本取回来包成 `File`，塞进页面的
   `<input type="file">` 再触发 `change` —— 站点自己的上传处理器（例如 send 站点的
   `uploadPicked`）照常跑：存到「待分类」、进度提示、失败处理都不变；
3. 页面里没有上传入口、或文件取不回来时，App 提示一句，点页面上的上传入口照旧能传
   （那条路打开文件选择器时 App 会把分享的文件直接回填，不用再翻一遍相册）。

网页端自己做不了这一步：网页读不到 `content://`，也没法在没有用户手势时打开文件选择器，
所以「分享完自动保存」只能由 App 把文件送进页面的输入框。文件全程流式读取，不复制、不改名、
不进内存；读相册文件要权限——Android 13+ 是「照片和视频」（`READ_MEDIA_IMAGES/VIDEO/AUDIO`），
更早版本是存储权限，第一次分享时申请一次。

### 方式 L：语音朗读与录音（v1.0.31 起）

Android 的 WebView 不实现 Web Speech API（`window.speechSynthesis` 整个不存在），学习类站点
（轰轰爱学习等）的朗读只能弹「浏览器不支持语音合成」；网页录音用的 `getUserMedia` 又只在
**安全上下文**（https）里才暴露，站点里的语音跟读一直点不动。两件事现在都由 App 补齐：

**① 语音合成（朗读）**——注入脚本用 App 的系统 TTS 补齐 `speechSynthesis` /
`SpeechSynthesisUtterance`，语义照浏览器来：

- `speak()` / `cancel()` 转给系统 TTS，播完/出错回调页面的 `onend` / `onerror`；
  「一句念完接下一句」的链式朗读、`cancel()` 之后旧句不再回调，都按浏览器行为实现；
- `getVoices()` 列出系统 TTS 引擎的嗓音（普通话统一标成 `zh-CN`，页面按 `zh` 挑嗓音挑得中）；
  引擎刚就绪时补发一次 `voiceschanged`（不会和 `getVoices()` 转圈）；
- 空 utterance（手机端「解锁 TTS」的常见写法）当场收尾，不占队列；
- 系统 TTS 没有中文数据时回 `error`，页面可以走自己的降级（预录音 MP3 等），而不是静默无声；
  这时 App 还会弹一次提示（「朗读失败：…… 请到 设置 → 无障碍 → 文字转语音 里检查」），
  告诉用户该去哪儿装引擎或中文语音，而不是让人对着没声音的按钮猜。

清单里那条 `<queries><intent><action android:name="android.intent.action.TTS_SERVICE" /></intent></queries>`
不能删：Android 11 起（targetSdk ≥ 30）有包可见性限制，不声明就看不见任何 TTS 引擎，
`TextToSpeech` 初始化直接返回 ERROR、`getVoices()` 为空、所有朗读静默失败，而网页里的 MP3 播放
完全不受影响——症状就是「组词、造句没声音，点汉字本身有声音」。排查用 `adb logcat -s WebShareApp`
看 `TTS init status=...`（`status=0` 才算拿到引擎）。

朗读用的是手机的系统 TTS 引擎（设置 → 无障碍 / 语言和输入 → 文字转语音输出），要换嗓音在那里装/选。

**② 录音（语音跟读）**——WebView 侧放行麦克风：`onPermissionRequest` + `RECORD_AUDIO` 运行时权限，
第一次录音时系统弹「仅在使用该应用时允许」。但 Chromium 只在安全上下文里把麦克风交给网页，
**`http://` 局域网地址下网页拿不到麦克风**（页面一般提示「不支持录音功能」），要用 https 地址打开。
以轰轰爱学习为例：`http://192.168.31.76:8010` 只能朗读、不能跟读；
`https://hanzi.nbhonghong.top:7777`（Lucky 反代 + 泛域名证书）朗读、跟读都能用。

### 方式 M：网页里「打开 App」的链接（v1.0.36 起）

网页里点一条要跳别的 App 的链接（豆瓣的 `douban://douban.com/movie/35465232`、`weixin://…`，
或 Chrome 那套 `intent://…#Intent;scheme=…;package=…;end`），App 会在底栏上方弹一条提示：

```
[图标] 此网站请求打开 App     打开  ✕
       豆瓣
```

点「打开」才真的跳走（和 Chrome 一样，不是偷偷跳）；点 ✕ 关上。几个细节：

- **认得出目标 App** 时提示条显示它的真实名字和图标；认不出（没装、或只认识 scheme）就显示
  按 scheme 猜的中文名（豆瓣/微博/知乎…），再不认识显示「其他应用」——点「打开」会告诉你
  「手机上没装能打开这个链接的应用」。
- `intent://` 里带的 `browser_fallback_url`（网页说「App 打不开就用浏览器打开这个网址」）
  会在打不开时自动在当前标签页里打开。
- 页面脚本自己在背后乱跳的**陌生** scheme（统计、拉活用的 `adssdk://` 之类）不会弹条，
  日志里记一句 `忽略脚本跳转的 scheme: …`；`about:` / `data:` / `blob:` / `file:` 这些网页
  自己的伪协议照旧交给 WebView，不当成「打开别的 App」。
- 清单里的 `<queries>` 同样不能删：**没有这些 scheme 的声明，Android 11+ 的包可见性会让
  `resolveActivity` 直接返回空、`startActivity` 抛 `ActivityNotFoundException`**——症状就是
  「点豆瓣链接完全没反应」（旧的代码把异常吞掉了，所以连报错都看不到）。要支持新站点，
  在 `<queries>` 里照格式加一条 `<data android:scheme="…" />` 即可。
- 注入页面的脚本原本会把所有 `target="_blank"` 的链接转交系统浏览器（方式 I 的「新窗口
  打开」）；而日历的豆瓣条目恰恰是 `<a data-app="douban://…" target="_blank">`——capture 相
  先劫持走，页面自己的处理器看到 `defaultPrevented` 就放弃，结果点了只会跳到系统浏览器的
  **网页版**。现在这类带 `data-app`（网页自己声明的「开 App」链接）会被放行给页面处理器，
  由它发起 `douban://` 再被 App 拦下弹条。

### 方式 N：记住登录 & 语音直达某个页面（v1.0.39 起）

**① 记住网站登录（Cookie）。** 登录过的站点（包括政务站点那种登录时要在好几个域名之间跳的统一认证）
不用每次重新登录。App 做三件事：页面加载完和退到后台时把 Cookie 落盘、显式接受第三方 Cookie
（跨域名登录必需）、**长按三条线菜单里的「刷新」**（v1.0.75 起恢复；v1.0.67 之前也在那里）
**只清缓存不再清 Cookie**（旧版本顺手把 Cookie 一起清了，
所以"强制刷新一下 = 所有网站都退出登录"）。要清登录状态是设置页里一个单独的按钮
「清除所有网站登录状态（Cookie）」——只清 Cookie，不动网页缓存。

**② 语音快捷指令。** 设置 → 「语音快捷指令」：填「名称 + 网址」加一条，比如名称「乘车码」网址填
乘车码页面。加好之后有三条路进这个页面：

| 怎么触发 | 前提 | 效果 |
| --- | --- | --- |
| 长按桌面上的 App 图标 → 点「乘车码」 | 无 | 直接打开这条网址（动态快捷方式，最多 5 条） |
| 对小艺说「打开 + 应用名 + 乘车码」 | 手机助手支持**按快捷方式名**直达 | 直接打开这条网址 |
| 对小艺说「打开 + 应用名」（只开 App） | 设置里把「语音助手打开时」设成这条 | App 认出来是助手唤起的，直接进这页 |
| 对小艺说「打开 + 应用名 + 标签页备注名」 | **无**（v1.0.44 起：标签页备注名自己就是快捷指令） | 切到那个已经在开着的标签页（页面上还留着你上次的位置） |

**更方便的一条（v1.0.44 起）**：不用去设置页加条目 —— 直接在标签页切换器里**长按标签页标题栏**，
给它起个备注名（比如把乘车码那页叫「乘车码」），这个名字就自动变成一条快捷指令。
之后对小艺说「打开DNS浏览器乘车码」，或者长按桌面图标点「乘车码」，都会**切到那个标签页**
（标签页已经关掉时会按记录的网址新开一页）。备注名留空确定＝恢复网页原来的标题。

第三条路把「设置 → 语音快捷指令 → 语音助手打开时：直接进『乘车码』」设好即可：App 每次启动都会
看一眼"这次是谁把我叫起来的"（referrer 包名，华为助手是 `com.huawei.vassistant`；桌面图标点开是
`com.huawei.android.launcher`，不会误跳），设置页最下面会显示上次是谁唤起的，好核对。
外部工具也能用它：`webshare://voice/<条目 id>` 这个深链（清单里注册了 `webshare` scheme）一开就直达
对应页面；标签页备注名那条用的是 `webshare://voice/tab:<备注名>`（备注名按需做 URL 编码，
比如「乘车码」＝`tab%3A%E4%B9%98%E8%BD%A6%E7%A0%81`）。

应用显示名是**「DNS浏览器」**（v1.0.43 起；之前叫「网页分享助手」），所以「打开DNS浏览器乘车码」
这种说法里"应用名"就是它。小艺能不能听这句、听成哪个动作，取决于手机自己的指令解析：只按名把 App
打开时，靠上面第三条路照样直达；完全不认这个说法时，到手机的「快捷指令」里建一条自定义指令
（触发语「打开dns乘车码」→ 执行「打开应用 → DNS浏览器」）即可。

### 方式 O：单页应用的「登录回来别把我扔去首页」适配（v1.0.48 起）

有的站点登录之后不把你送回原来那页，而是按服务端配置挑一个"落点"，普通浏览器用户就被扔到首页。
典型是**厦门 i人才**（`xmirc.xmdjej.gov.cn/italent/talentTraffic`）：打开 `/rideCode/index`（刷码乘车）
时若本地没有登录态，页面会先跳市民卡统一认证，回来后由服务端 `POST /h5/stateConfig?state=<进站来源>`
决定去哪 —— 来源标识缺省是 `index`，它就回你一句"去首页"，于是 `location.replace(.../rideCode/talent)`，
想看刷码乘车最后落在人才服务首页（在那儿点"出行礼遇"还会弹「请从首页"人才出行"或者"出行礼遇"
入口进入该服务」）。站点没有给普通浏览器留回原页的按钮。

App 侧的补法（`assets/shim.js` 里 `keepRideCodePage()`，注入在主框架 HTML 最前面，整页加载前就跑）：
记住用户当前在等哪一页（`/rideCode/index`、`/travelRecord`、`/useHelp` 写进 `sessionStorage`，
跨域登录跳转和整页刷新都不丢；单页应用内部的跳转也会同步更新），一旦发现**刚走过登录回调页又被扔到
首页**，就把用户带回原页。只看整页加载，所以自己在页面里点去首页不受影响；离开这几个内容页时意向
立即作废；同一目标 15 秒内最多回弹 3 次，避免和服务端打成死循环。这个适配只对这一个站点生效，
其它网站的行为一个字节都不变。

### 方式 P：到某地自动打开（坐标规则）（v1.0.50 起）

设置页最下面那张卡「到某地自动打开」：填一个坐标（点「用当前位置填入」直接填你现在站的地方）、
一个范围（米，默认 300）和一个网址（点右边图标能从语音快捷指令 / 标签页备注名里挑）。开关打开后，
**每次打开 App**（点桌面图标 / 最近任务）的那一刻读一次位置：人在范围内就自动打开你设的那一页，
不在范围内照常打开普通页面。

- 典型用法：坐标设成「吕厝公交站」，网址设成乘车码页 —— 走到站台再打开 App 直接就是乘车码，
  不用再点标签页、也不用对小艺喊话。
- 判定在**打开 App 那一刻**做一次：没有后台定位、没有常驻服务、不上报任何数据。
  没给位置权限、系统定位关着、或者这次定位误差比范围还大（比如只拿到基站的粗定位），
  就什么都不做——宁可不动，也不在别处把人送错页（「测试一下」会把这一条明说）。
- **只认 1 分钟内的定位**（v1.0.51 起）：系统缓存里那条"最后已知位置"常常是几分钟前站在目标点时
  留下的，人早走开了却还报"距目标 0 米"（真机上踩到过）。所以比 1 分钟旧的位置一律不当数，
  改成当场重新要一次（最多等 6 秒，这一轮只要新位置）；要到的还是更早的位置就**不判**，
  照常打开普通页面，日志/设置页会说明"只拿到 N 分钟前的定位"。
- 要位置这几秒里你要是自己动了（翻了标签页、开了新标签页、页面跳去别的站点），就不再抢你的页面。
  **恢复出来的标签页冷启动那次自己的加载不算"你动了"**，否则这功能会永远不生效。
- 每次打开都重判一次：走到站台时 App 多半还在后台，从桌面点一下照样生效（v1.0.50 起）。
- 命中时：当前这一页还是空的（刚清空标签页 / 全新安装）就**就地**换成设定页，否则在新标签页打开
  ——同一个地址已经有标签页就切过去，不会越开越多。
- 分享内容给 App、点通知进来这两种情况不判（它们本来就有明确的目标页）。
- 位置权限只在开关打开时申请一次（`ACCESS_COARSE/FINE_LOCATION`，只在前台用；清单里
  `android.hardware.location` 标了 `required="false"`，没有定位硬件的设备照装不误）。

### 方式 Q：缓存视频、离线看（v1.0.52 起，v1.0.54 起合进「已下载」）

**点右下角三条线打开菜单，长按「已下载」**（约 0.5 秒）就开始缓存当前这一页的视频：只发现一个就直接开始，有好几个就列出来
让你挑，一个都没有会提示「先在网页里点播放」。进度在通知栏（渠道「视频缓存」，带取消），存好了点通知
直接进「已下载 → 缓存视频」；平时点「已下载」也能进去看，页面上方两个标签「下载记录 / 缓存视频」切换。

- **缓存完不联网也能看**：视频存在 App 自己的目录里（`Android/data/com.webshare.app/files/videocache/`），
  播放走 App 内置的本机播放页 `http://127.0.0.1:<随机端口>/p/<随机口令>/<id>`（支持 Range，能拖进度条），
  跟原网站、跟网络都没关系了——出站路上刷剧、原站的视频被删了都不影响。
- **能缓存什么**：直链文件（mp4 / webm / mkv / mov …）、HLS 分片列表（`.m3u8`，TS 分片和 fMP4 分片都行）。
  多码率的播放列表会**自动挑码率最高的那一路**。地址上没有扩展名也认——服务器回的 `Content-Type`
  是视频就记下来（`/video/12345` 这种站点能用）。
- **自动处理的**：TS 分片拼起来后会用系统的 `MediaExtractor/MediaMuxer` **换成 mp4**（只换封装、不重编码，
  几秒钟），这样任何播放器/相册都认，分享出去也不会「格式不支持」；换不成就保留 `.ts`，并让播放页按
  TS 如实声明类型。
- **明说不支持的**：加密的 HLS（`EXT-X-KEY` 不是 NONE）和用 `EXT-X-BYTERANGE` 的分片会直接拒绝，
  通知里写明原因（不去偷学密钥、也不拼半个文件出来）；DASH（`.mpd`）同理。
- **缓存视频标签**每条能做四件事：**播放**（就在本浏览器里打开离线播放页）、**存到手机**（走「下载记录」
  那套，落到系统下载目录或你自己选的目录）、**分享**（`FileProvider`，微信/QQ 这类收得到）、**删除**；
  右上角「清空缓存」一次清干净。标签上写着缓存了几个。
- **不打扰**：只在 App 里认页面上的视频源，不往页面里插东西、不改网页内容；也不会自动浮提示条——想让
  App 缓存时才长按。本机播放地址（127.0.0.1）不走 DoH、也不会被当成「发现视频」。

### 方式 R：安卓电视 / 遥控器（v1.0.53 起）

把 APK 用 U 盘或 ADB 装到电视（Android TV、索尼 BRAVIA 这类）后，电视桌面（Leanback）里就能找到
「DNS浏览器」，图标下是 320×180 的电视横幅。遥控器怎么用：

- **方向键 = 移动屏幕上的小圆点光标**，**OK = 在小圆点处点一下**。这个点击是发给网页的**真实触摸事件**
  （不是脚本模拟点击），所以链接跳转、表单提交、输入框聚焦都和手指点一样；点开的页面按返回键能正常回到
  上一页，不会被当成「替换当前页面」。
- **长按 OK**（约 0.6 秒）或按**菜单键**把焦点切到底栏，落在**当前页的标签圆片**上；左右可以逐个
  选中圆片（**选中的圆片会放大一圈，并套上深色外圈 + 白色内圈的双环**，一眼能看出焦点在标签条），
  **选中后按 OK 才切换页面**。再往右经过翻页箭头就是**三条线按钮**，
  按 OK 竖向弹出「新建页面 / 标签页 / 刷新 / 已下载 / 设置」（焦点落在第一项「新建页面」），上下选、OK 按下；
  「新建页面」打开的地址栏和切换器里那套一样（默认网址 + 最近访问过的地址）；
  按 ↑ 或再按一次菜单键回到网页。
  长按之后松手不会再顺带点一下光标处。返回键先收起菜单，再按一次把焦点还给网页。
- **网页是两段式**（v1.0.56 起）：从工具栏按 ↑ 回到网页时只是**选中网页**——四周画一圈紫框，
  不显示光标，方向键也不会挪它；**再按一次 OK 才进入页面光标模式**。想回工具栏：长按 OK / 菜单键，
  或在"只选中网页"时按 ↓。这样不会出现"只想选中页面却一下点进了某个链接"。
  **返回键是一级一级退的**：光标模式里按返回只是退出光标模式（回到"网页被选中"，v1.0.58 起）；
  页面没有上一页时按返回先回工具栏、焦点落在当前标签圆片，并提示"再按一次返回退出应用"；
  在工具栏再按返回才退出应用（标签页保留，v1.0.59 起）。页面有上一页时仍按历史后退。
- **缓存当前页的视频**：先长按 OK 切到工具栏，打开三条线菜单，把焦点挪到「已下载」再**长按 OK**——
  和手机上长按「已下载」是同一个入口（一个候选直接开始，多个弹列表让遥控器挑）。
- **标签页切换器（电视专用操作条，v1.0.62 起）**：打开三条线菜单 → 选「标签页」打开切换器后
  （v1.0.77 起从这里进；原来在长按圆片的菜单里叫「标签页列表」），遥控器焦点直接落在
  **当前标签页的卡片**上（整张卡片套**深色外环 + 白色内环**的双环焦点框，浅紫的"当前页"卡片上也看得清）；
  ←/→ 在卡片间移动，↓ 从最后一行落到切换器底部的
  **「＋ 新建标签页 / 模式 / 编辑 / 关闭」**操作条。按 OK 选中卡片就是切过去；选中 **编辑** 打开「编辑标签页」
  （备注名、页面字；手机从卡片菜单的「编辑页面」进同一个对话框）；选中 **关闭** 关掉焦点所在的卡片，关完焦点
  自动挪到下一张。每张卡片右上角的 ✕ 也能直接选中关闭。在切换器里关掉当前页不会把焦点抢回网页。
  **卡片左边还有一列竖着的「＋ 新建」**（v1.0.67 起，高度和第一行卡片一致）：第一列卡片按 ← 选中它，
  按 OK 直接弹出新建标签页的地址栏（和底部「新建标签页」同一个对话框）。
- **长按圆片/卡片弹标签页菜单**（卡片 v1.0.67 起，圆片 v1.0.69 起直接弹）：遥控器在底栏圆片或
  切换器卡片上**按住 OK 约 0.6 秒**弹出菜单，焦点直接落在第一项，↑/↓ 选、OK 确认：
  **编辑页面**（网址 / 备注名 / 页面字）、**页面操作方式**（电视上）、
  **关闭页面**（红色，关完焦点交给下一张卡片）。菜单弹在圆片/卡片正上方（v1.0.77 起）。
  短按圆片仍是切换页面。按返回或点菜单外面收起。
  **松手后才弹**，避免按键抬起那一下把菜单第一项点掉。
  菜单样式与右下角三条线菜单一致（v1.0.75 起：48dp 行高、紫色图标、单行文字，
  底部靠右的小面板，不压暗网页）。
- **每个标签页的电视操作方式（v1.0.65 起）**：焦点落在某张卡片上时，按操作条的 **模式**（或卡片菜单里的
  **页面操作方式**）可以在 **「鼠标」↔「方向键」** 之间切换这一页（按钮文字会跟着显示当前模式），
  设置记在标签页记录里、重启后还在。切到「方向键」的卡片，标题右侧会标一个紫色的「方向键」。
  - **鼠标**（默认）：按 OK 进入网页后出现小圆点，方向键挪圆点、OK 点击——适合普通网页。
  - **方向键**：按 OK 进入网页后**不出现圆点**，方向键直接在页面里的链接/按钮/输入框之间按位置移动焦点
    （焦点框是紫色 3px 描边），OK 点击聚焦的元素；焦点落到输入框会自动弹出电视键盘。
    那个方向没有可去的元素时，方向键照常滚动页面。
- **输入框**：先按 OK 进入网页，把圆点移到输入框上按 OK，电视会弹出它自己的输入法；打字时方向键
  归输入法，不会把光标挪走。按返回先收起键盘，再按返回就退出输入状态（光标重新能用）。
  **输入法弹出、网页视口缩小时，网页四周那圈紫色焦点框会先收起来**，收起键盘后再画回去
  （v1.0.67 起）——不然框会跟着缩小的视口错位，看起来像是跑偏了。
  **App 自己的输入框**（新建标签页的地址栏、编辑标签页的备注名/页面字，v1.0.62 起）打开时自动
  把焦点放进第一个输入框并主动叫出电视输入法；网页里的输入框点中后也会补一次
  `showSoftInput`（有些电视/模拟器只给 `<input>` 焦点却不弹键盘，最多重试两次）。
- **网页全屏**：网页里视频/元素自己的「全屏」按钮可用，会盖住整屏，返回先退出全屏。
- **离线播放页**（「已下载 → 缓存视频」里点「播放」）：大屏下视频铺满播放区、标题浮在左上角；
  ←/→ 快退/快进 10 秒，OK 暂停/继续，↑/↓ 调音量（播放页里这些键不会移动光标）。
- 手机上这些都不生效（按设备有没有 Leanback / 电视特性判断），触摸操作完全不变。

### 方式 S：新底栏与三条线菜单（v1.0.55 起）

底栏（高 56dp，电视上 40dp）分成两半。电视上特意压到 40dp（v1.0.72 起）：按 `100dvh`
铺满一屏的网页（比如家庭日历）最底下一行图例容易被切掉，压低后正好让出来；28dp 的圆片和
聚焦放大 1.3 倍仍然装得下。

- **左边是标签页圆片**：每个圆片一个 28dp 的圆，里面是这一页的**页面字**——单独设过就用它，
  否则取备注名/标题的第一个字（中文取第一个汉字，英文自动大写，书名号/引号这类字符自动跳过）。
  当前页紫色（白字），其它页浅灰（深灰字）。点圆片切过去；圆片总宽超出可视区时两侧自动出现
  **‹ / ›** 按钮（按住可连续翻），标签条本身也支持手指横滑。

## 技术说明

### DoH 实现原理

当 DoH 开启时，应用通过 `WebViewClient.shouldInterceptRequest` 拦截 WebView 的 GET 请求，使用 OkHttp 发起请求并通过自定义 DNS 解析器（`DohDnsResolver`）进行域名解析。DNS 查询通过 HTTPS 发送到配置的 DoH 服务器，实现加密 DNS 查询。

**注意事项：**
- WebView 的 `shouldInterceptRequest` 仅拦截 GET 请求（主页面与子资源加载）
- JS 发起的 POST 等请求：v1.0.11 起通过自动注入脚本接管 fetch/XHR，原生请求失败时走 App 内部 DoH 通道（见"方式 E"）
- Cookie 通过 `CookieManager` 在 WebView 和 OkHttp 之间自动同步
- 子资源（图片/视频/脚本）拦截失败时返回 `null` 交给 WebView 处理，**不会**塞 HTML 错误页——
  否则 `<video>` 会把网络错误报成"解码失败"，页面的重试/转码逻辑会被带偏
- **主框架（主页面）的 301/302 不由 App 内部跟完，而是整条导航交回 WebView**（v1.0.41 起）：
  代理内部把跳转跟完会把页面挂在**跳转前的地址**下，页面里的相对路径（`js/chunk-vendors.js`
  这种）就会解析到错的目录——厦门乘车码的登录页正是这么白屏的（JS 取回来是 200 +
  `application/json`，内核按「MIME 不可执行」拒绝执行）。`WebResourceResponse` 本身不允许
  3xx 状态码，所以做法是「发现要跳转就返回 `null` 不拦」，让 WebView 照标准跳（地址栏、
  相对路径基址、同域判断才对）。子资源仍照旧内部跟跳。代价：被交回的**这一跳**不走自定义
  DNS——只认自定义 DNS 的站点若又恰好整站跳转，可能连不上（日常站点不受影响）
- 页面是 `http://` 源、而站点实际只开 TLS（端口 7777）时，网页原生 POST 必然被重置，
  此时全靠注入脚本的桥接兜底；桥接内部会在 http / https 之间自动回退
- 下载与上传走 `HttpEngine`（流式，不整包进内存）；下载交给前台服务，
  应用切到后台或息屏也能继续
- 已开启 `setWebContentsDebuggingEnabled`，可用 `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`
  连 Chrome DevTools 调试页面

### 网页视频：能力上报与录像修复

**能力上报**（`MediaCaps.kt` + `shim.js`）——`MediaCodecList(ALL_CODECS)` 里跳过 encoder，
按 `isHardwareAccelerated`（Android 10+）/ 解码器名字（更早版本）判断 H.265 是硬解还是软解，
结果给注入脚本；脚本只在「设备完全没有 H.265 解码器」时才把 `canPlayType` /
`MediaSource.isTypeSupported` 的 hevc/h265 答案改成空串 / false。VP9（libvpx）和 AV1（dav1d）
是 Chrome 自带软解，不能跟着一起降级，否则本来能播的 B 站 AV1 视频反而播不了。

**时间轴修复**（`MediaRepair.kt`）——**只改文件自己的采样表，采样数据一个字节都不动**：
解析 moov 里的 stts / stsz / stsc / stco / stss（有 ctts 也处理），判定规则是「相邻样本时间差
`0 ≤ Δ < 1000µs` 且这种样本 ≥ 3 个」算塌陷，从塌陷的第一个样本起整段丢弃，然后把每张表截断
（盒子总长保持不变、多余位置补 0，所以 mdat 里样本的字节位置和 stco 里的偏移一个都不用改），
改 mdhd / tkhd / mvhd 时长，最后按保留样本的末字节把 mdat 尾段砍掉。效果等同
`ffmpeg -t <截断点> -c copy`，既不依赖 ffmpeg，也不经过 `MediaMuxer`。
判定阈值不能放宽：B 帧会导致 PTS 逆序（差值为负），把负差也算成损坏会误伤 B 帧视频——
早期一条 `Δ < max(2000, 自然间隔/4)` 的规则就曾把 321 个健康视频里的 296 个砍成残废，
现在这条规则在全站 349 个视频上跑，命中的 24 个全部是门锁录像、零误伤。
修完立刻用同一个解析器把结果读回来自检（每条轨道的样本数与预期一致、首帧仍在 0、时间轴不再塌陷），
通过才写缓存；缓存按 URL 的 MD5，目录带规则版本号（`video-repair-r4`），换规则自动失效。
每次尝试都会在缓存目录留一个 `<md5>.trace.txt`，记录解析与判定过程，
`adb pull` 出来就能回答「为什么这个视频没修 / 修掉了多少帧」。

**为什么不用 MediaExtractor + MediaMuxer 重封装**（v1.0.19 之前的两次返工）：

1. `MediaExtractor` 枚举 + `MediaMuxer` 重封装：实测这类文件上 `MediaExtractor` 会漏掉文件自己的
   第 0 号样本（PTS=0 的那个关键帧），开头几帧的 SYNC 标志也报成 0；`MediaMuxer` 见首个视频样本
   不是关键帧，就把它之前的样本整段丢掉——修出来的文件视频从 0.889s 才开始、音频却从 0 开始，
   音画错位 0.889s，开头 11 帧真实画面永久丢失。
2. 改成自己读采样表、只把样本数据交给 `MediaMuxer` 写：`MediaMuxer` 对 AVC/HEVC 样本会做
   「Annex-B → 长度前缀」的转换，而文件里的样本本来就是长度前缀格式，找不到起始码，
   于是整段被当成一个 NAL 又套了一层长度前缀（每帧多 4 字节）。实测 ffmpeg 解出 0 帧、
   WebView 77 帧里只解出 2 帧——画面根本没出来，只有声音在走。
   现在改成原地改表，以上两种平台行为都不再影响结果。

**踩过的坑：整份交付 vs Range / 206**——站点对本地录像按 `Range` 回 206，而 WebView 的媒体管线
拿到一串被截断 / 反复重取的 206 时，会在第一个 GOP 之后报 `MEDIA_ERR_DECODE`（实测：同一份字节
用不支持 Range 的服务器整个 200 发过去能完整播完，用 206 分段就只能播 0.9 秒）。所以现在对
「从 0 开始」的视频请求，主动把 `Range` 放大成 `bytes=0-<64MB-1>`，拿到整份后以 **200 + 完整 body**
交回去，并把 `Content-Range` / `Content-Length` / **`Accept-Ranges`** 一起删掉。`Accept-Ranges`
不能留：留着它 WebView 会在拿到整份之后又按 Range 回头再取一遍（实测 4.6MB 的文件整份交付后
又被请求了 `196608-` 那一段），而二次按 Range 取到的分段正是播不动的根源；去掉它，行为等同于
一台不支持 Range 的普通服务器。文件超过 64MB 时只拿得到一段，这时照原样按 Range 交回，不冒险吃内存。

改写响应体（录像修复）时同样必须删掉描述原始 body 的头部，否则 FFmpegDemuxer 会按错误的长度读，
报 `PIPELINE_ERROR_READ: FFmpegDemuxer: data source error`（`MEDIA_ERR_SRC_NOT_SUPPORTED`，
看起来像格式不支持，其实只是长度对不上）。

**下载路径**（`DownloadService.kt`）——下完后读回文件跑同一套 `MediaRepair`，修好了就覆盖写回，
识别不了 / 不需要修（返回 null）就保持原样，绝不动健康文件。

**分享进来的文件**（`MainActivity.kt` + `DohWebViewClient.kt`）——`ACTION_SEND` / `SEND_MULTIPLE`
的 `EXTRA_STREAM` 取 `content://`：先登记进 `WebAppInterface` 的「刚选过的文件」表（multipart 上传
按 文件名+大小 找内容）。**自动上传**走这样一条路：文件挂到同源虚拟地址
`/__webshare__/shared/<token>`（拦截器本地应答，不落盘、不出网，token 每次分享都换），页面加载完
注入脚本 `fetch` 回来包成 `File`，塞进页面第一个 `<input type="file">` 并派发 `change` ——
站点自己的上传逻辑照常跑，用户零点击；页面若想接管，声明 `window.webshareAutoUpload(files)` 即可。
注入结果写进 `window.__webshareAutoUploadResult`，App 读回来决定提示（`dispatched` / `hook` /
`no-input` / `error: ...`）。兜底：页面开文件选择器时把分享的文件直接回填（`onShowFileChooser`，
类型不匹配才回退到普通选择器）。`EXTRA_STREAM` 既可能是单个 `Uri` 也可能是 `List`，直接从 extras
里按类型取，不走 `getParcelableExtra`（后者在类型不符时可能抛 `ClassCastException`）。读相册文件要
`READ_MEDIA_VIDEO` / `READ_MEDIA_AUDIO`（13+）或 `READ_EXTERNAL_STORAGE`（≤12）——只声明
`READ_MEDIA_IMAGES` 时 MediaProvider 会对视频 uri 抛
`SecurityException: com.webshare.app has no access to content://media/...`，清单里补齐、
首次分享时申请一次。

### 缓存视频的实现（v1.0.52 起，v1.0.54 起合进「已下载」）

**入口**（`MainActivity.kt`）——三条线菜单里的「已下载」挂 `setOnLongClickListener` → `startCacheFromPage()`：
取当前标签页 WebView 的 `MediaWatch.forView()` 候选，一个直接开始、多个弹 `AlertDialog` 列表、
没有候选就 Toast 提示先去播放。以前那条「发现视频」浮条（`mediaBar`）和底栏「缓存」入口都已删除；
`MediaWatch` 仍然照常收集候选，只是不再主动浮出来。

**发现**（`MediaWatch.kt`）——在 `shouldInterceptRequest` 里看每一跳 GET 的地址：`.m3u8/.m3u` 记成
HLS 候选、`.mpd` 记成 DASH、`.mp4/.webm/...` 记成直链；同一个页面一旦有 HLS 候选，后面的分片
（`.ts/.m4s`）就不再单独记（它们要靠播放列表才拼得回来），每个页面最多留 6 条。地址认不出来的
（`/video/12345`、`/stream?src=…`）靠**响应头**补记：走我们自己通道拿到的 `Content-Type` 是视频就记下来。
⚠️ 记候选发生在 WebView 的拦截线程上，那里**不能碰 WebView 的任何方法**（`view.url` 会抛
`A WebView method was called on thread`）——页面地址由主线程的 `onPageStarted` 通过 `setPageUrl` 记。
本机地址（127.0.0.1 / localhost / 分享用的虚拟地址）在拦截器开头就 `return null`：不走 DoH、
不做整份交付、也不记成"发现视频"。

**下载**（`VideoCacheService.kt` + `VideoCache.kt`）——前台服务（`dataSync`）串行跑队列，进度发通知栏
（渠道「视频缓存」，通知带「取消」，正在缓存的那一条可以取消）。直链走 `HttpEngine`（同一个 DoH /
Cookie 通道，`Referer` 带原页面）；HLS 先取播放列表，多码率（`#EXT-X-STREAM-INF`）挑 BANDWIDTH 最高
的一路，`#EXT-X-MAP` 的初始化段拼在最前面（fMP4 拼出来就是 mp4），TS 拼完用
`MediaExtractor/MediaMuxer` 换封装成 mp4（失败就留 `.ts` 并由播放页按 `video/mp2t` 声明）。
下一个文件之前先看剩余空间，不够就当场报错、不留半个文件。缓存完成的通知带
`DownloadsActivity.EXTRA_TAB=cache`，点通知直接落在「已下载」页的缓存标签。

**离线播放**（`LocalMediaServer.kt`）——只听 `127.0.0.1` 的小 HTTP 服务（随机端口 + 路径里的随机口令，
同机别的 App 猜不到）：`/p/<口令>/<id>` 是内置播放页（`<video>` 直接指同源的 `/v/<口令>/<id>`），
`/v/...` 是视频文件本身，支持 `Range`/206（所以进度条能拖），按扩展名给 `video/mp4`、`video/mp2t` 等类型。
播放页只是 App 里的一页：点「播放」用 `webshare://play/<id>`（`CLEAR_TOP|SINGLE_TOP` 复用同一个浏览器
实例）打开，返回键按浏览器自己的历史走（播放前那一页）。

**已下载页的两个标签**（`DownloadsActivity.kt` + `activity_downloads.xml`）——「下载记录」是原来的
下载历史（轮询进度、批量操作原样保留）；「缓存视频」是缓存列表（播放 / 保存到本地 / 分享 / 删除 /
清空）。两个 RecyclerView 叠在同一块区域按标签切换，`activeTab` 决定顶栏「清空」按钮做哪件事；
800ms 轮询顺带刷新缓存列表，但只有内容签名变了才 `notifyDataSetChanged()`，免得电视上焦点被反复冲掉。
电视上标签本身可聚焦，切到缓存标签会把焦点落到第一条。

**顺带修的一处**：`DohDnsResolver` 现在看到地址本身就是 IP（127.0.0.1、内网地址、IPv6）就直接返回，
不再拿去问 DoH ——否则"保存到手机"里那个 `http://127.0.0.1:...` 的下载源会解析失败。

**落盘**：`Android/data/com.webshare.app/files/videocache/`（一个视频一个文件 + `index.json` 索引，
文件名是 `<时间戳>-<标题>.mp4`）。删除 / 清空会连文件一起删；分享走
`FileProvider`（authority `${applicationId}.fileprovider`，只暴露 `videocache/` 这一层）；
「存到手机」借用「已下载」那套（`DownloadService` 从本机地址读、写进系统下载目录或用户选的目录）。

### 电视兼容的实现（v1.0.53）

**能被电视找到**：清单里声明 `android.software.leanback` / `android.hardware.touchscreen`
都是 `required="false"`（电视没有触摸屏），MainActivity 加 `LEANBACK_LAUNCHER` 入口，
`<application android:banner>` 指到 320×180 的 `tv_banner`。判定「是不是电视」看 Leanback /
`android.hardware.type.television`；调试时可以用 `am start … --ez tv_mode true` 强制打开（记在
`webshare_tv/forced` 里，已下载页也认这个开关，模拟器上能一起验）。

**虚拟光标**（`shim.js` 里的 `tv`）——页面里插一个 fixed 定位的圆点，坐标是 CSS px；方向键由
`MainActivity.dispatchKeyEvent` 转发 `__wsTvMove(dx,dy)`，一步 `max(18, innerWidth/40)`（960 宽的电视是
24px，太粗会跨过只有一行高的输入框），按住方向键超过 6 次重复后每步 3 倍加速。光标顶到屏幕边会先滚
光标下面的滚动容器、再滚整页。

**点击为什么用真实触摸**：OK 松开时取 `__wsTvPoint()`（x/y/dpr），按 `x*dpr, y*dpr` 给 WebView
`dispatchTouchEvent` 发 ACTION_DOWN/UP。不能在页面里只调 `element.click()`：WebView 不把脚本点击当
用户手势，站内跳转会被 Chromium 当成**替换当前历史**，表现就是「光标点开一页，按返回直接退出」。
真实触摸事件走手势识别，历史记录是对的（实测 `history.length` 从 1 变 2、`canGoBack=true`）。
另外本机播放页（`127.0.0.1/p/…`）里的按键不拦，交给页面自己的 ←/→/OK/↑/↓ 处理。

**输入**：页面在 `focusin/focusout` 时通过 JS 桥 `Android.tvEditing(bool)` 告诉原生「正在输入」，
`pageEditing` 为真时方向键原样交给 WebView（不然打字时方向键在挪光标）。点输入框后 300ms 若输入法
还没起来，补一次 `showSoftInput`——注意**不能先 `webView.requestFocus()`**，WebView 会顺手把键盘焦点
还给页面上第一个可聚焦元素（实测输入框刚拿到焦点就被挪到按钮上，输入法随即被收起）。返回键在输入
状态里先收键盘、再 blur 输入框，光标恢复可用。

**焦点**：网页和工具栏在同一套焦点体系里——标签页圆片、左右翻页箭头、三条线按钮、四个菜单项、
浮条按钮、标签页卡片/关闭按钮/「新建标签页」、已下载页的两个标签都设 `isFocusable` 并挂
`bg_tv_focus` 焦点框。**`HorizontalScrollView` 必须 `focusable=false`**（否则它自己会抢焦点，
左右键只滚标签条、选不中圆片）；圆片之间再用 `nextFocusLeftId/RightId` 显式串成一条链，
箭头和三条线按钮接在链的两端，箭头显隐变化时重绑。工具栏每项 `nextFocusUpId` 指回 WebView，
网页/浮条按钮的 `nextFocusDownId` 指向当前标签圆片。菜单项之间显式串成
新建页面→刷新→已下载→设置，最后一项按「下」回到三条线按钮；菜单打开时焦点落在「新建页面」，
三条线按钮的上下左右都被吸在菜单里。

**网页作为控件（v1.0.56）**：`tvPageActive` 区分「网页被选中」和「已进入网页」。焦点刚落到
WebView 时只画 `bg_tv_page_focus` 紫框（`foreground`），不调 `__wsTvShow(true)`；方向键在原生层
被消费（↓ 回工具栏），按 OK 才置 `tvPageActive=true` 并显示光标。聚焦切换/换标签/从自己的页面
返回时一律复位为 false，避免误点。`onPageFinished` 也只在 `hasFocus && tvPageActive` 时才恢复光标。

标签页切换器是
整屏浮层，打开时把底栏 `descendantFocusability` 设成 `FOCUS_BLOCK_DESCENDANTS`、WebView 设不可聚焦，
否则按 ↓ 会把焦点穿到浮层后面（真实复现：在切换器里按 ↓ 再 OK 打开了「已下载」）。网页全屏用
`WebChromeClient.onShowCustomView` 把视图挂到 decorView 最上层，返回先退出全屏。

**顺带修的历史问题**：部分 WebView（系统 WebView 132 上复现）`canGoBack()` 明明历史里有上一页却返回
false，`goBackOrForward(-1)` 也不动；返回键改成先让页面执行 `history.back()`（Blink 的历史是准的），
450ms 后地址没变再退回原生 `goBackOrForward(-1)`。没有上一页时返回键只退出应用、**不关标签页**
（v1.0.57 起；之前会顺手关掉当前标签页，用户刚新建的页按一下返回就没了）；关标签只能由用户在
切换器里点 ✕。
